# 技术实现说明

本文记录固件的实际实现状态、关键设计决策和踩过的坑，供维护者参考。
面向使用者的说明见 [USER_MANUAL](USER_MANUAL.md)，硬件与选型见 [WAVESHARE_DIY_GUIDE](WAVESHARE_DIY_GUIDE.md)。

---

## 1. 硬件接线（Waveshare 2.16）

| 外设 | 型号 | 接口 | 关键引脚 |
| --- | --- | --- | --- |
| 屏幕 | CO5300 | QSPI | CS=12, SCL=38, SIO0-3=4/5/6/7, RST=39 |
| 触摸 | CST9220 | I2C + INT | SCL=14, SDA=15, INT=11, RST=40 |
| IMU | QMI8658 | I2C + INT | INT1=17, INT2=21 |
| 电源 | AXP2101 | I2C 0x34 | — |
| RTC | PCF85063ATL | I2C 0x51 | INT=13 |
| 音频 | ES8311 + ES7210 | I2C + I2S | MCLK=42, BCLK=9, LRCK=45, DOUT=8, PA=46 |
| 按键 | BOOT / 用户键 | GPIO | GPIO0 / GPIO18 |
| SD 卡 | — | SDSPI | CMD=1, CLK=2, D0=3, CS=41 |

**注意**：

- GPIO0 是启动模式脚，运行时读数安全，**开机时按住会进下载模式**
- GPIO13 属于 RTC 中断，不要复用
- 2.16 板**未把 CO5300 TE 信号引到 ESP32**，所以不使用 TE 同步（1.75C 才用）

## 2. 显示链路

```
NavSnapshot → NavPresenter → moto_nav_ui_set_state → LVGL → CO5300 QSPI
```

- 画布固定 **480 × 480 RGB565**
- 双 PSRAM 缓冲，每块 320 行，直接 DMA
- QSPI 队列深度 1（保证 DMA 内存有界）
- 坐标使用**设计空间 360 px**，经 `px()` 缩放到实际 480 px

> 混用设计坐标和实像素会导致元素偏移。所有传给 `lv_obj_set_*` 的值都应经过 `px()`。

## 3. BLE 协议

自定义二进制协议，按帧分片（单帧最大 182 字节，对应 MTU 185）。

| 消息 | ID | 方向 |
| --- | --- | --- |
| ConnectionStatus | 0x01 | 双向 |
| Heartbeat | 0x02 | 双向 |
| Ack | 0x03 | 双向 |
| NavigationSnapshot | 0x10 | 手机 → 板 |
| RouteGeometry | 0x11 | 手机 → 板 |
| TrafficDeviation | 0x12 | 手机 → 板 |
| MediaState | 0x13 | 手机 → 板 |
| MapScene | 0x14 | 手机 → 板 |
| ClockState | 0x15 | 手机 → 板 |
| TripState | 0x16 | 手机 → 板 |
| DeviceCommand | 0x20 | 板 → 手机 |

设计要点：

- **版本化**：握手协商 `minimum_version` / `maximum_version`
- **分片 + CRC**：每帧带起始/结束标志，整包校验
- **心跳**：1 秒周期，用于检测链路失效
- **能力位**：`ConnectionStatus.capabilities` 声明支持的功能

协议规范见 [ble-navigation-v1.md](../shared/protocol/ble-navigation-v1.md)。

## 4. ANCS 通知

板子作为**外设**的同时，在手机建立的那条链路上充当 **GATT 客户端**，订阅 ANCS 服务。

### 必须知道的三件事

1. **只有锁屏才转发**：手机亮屏解锁时 iOS 把通知留在本地
2. **需要用户授权**：设置 → 蓝牙 → 设备旁 ⓘ → 共享系统通知
3. **只给 bundle id**：不返回显示名，需要本地映射表

### 踩过的坑：订阅瞬间的 ACL 拥塞

iOS 在 ANCS 订阅建立后会**重放整个通知中心的存量通知**，每条都带 `PreExisting` 标志。早期固件逐条回查正文，把 ACL 缓冲打满：

```
ACL buf alloc failed 5 times
MBUF alloc stuck
```

表现是**手机刚连上就卡死几秒**。

修复：识别 `PreExisting` 直接丢弃，不发起任何属性请求。

## 5. RTC 时钟

### 为什么需要

手机断开后，时钟页原本显示 `--:--`。板上 PCF85063 有独立晶振，可以继续走时。

### 实现

```
开机 → 从 RTC 读取 → 播种本地时钟
手机连接 → 推送分钟 → 与 RTC 比较 → 差 > 75 秒才回写
手机断开 → 本地时钟继续走时
```

### 两个容易错的地方

**1. 手机只发分钟，不发秒**

早期实现保留了 RTC 的旧秒数，导致 `15:05:01` 收到 "15:05" 后记成 `15:05:59`，58 秒后就跳到 15:06。**必须在收到推送时把秒清零**。

**2. 阈值不能太高**

原阈值 90 秒，配合分钟精度（天然差 0–59 秒），导致校正**几乎从不触发**，误差一路累积到几分钟。

现在 75 秒：`75 > 59` 保证不误触发，但真漂移超过一分钟就会拉回。

### 两字节年份

PCF85063 只存 `00..99`，世纪需要外部提供。首次写入时用**固件编译年份**兜底，之后记住写回的真实年份。

## 6. 语音提示

### 为什么不用流式 TTS

BLE 实测吞吐约 100 kbit/s，而 16 kHz 语音需要 256 kbit/s。流式播报会**断续**，在需要听清路口的时刻最糟。

### 方案：预渲染 + Flash

`scripts/generate_voice_phrases.sh` 用 macOS `say` 生成 17 段语音，存为 C 数组：

- 动作：左转、右转、掉头、环岛、到达、拥堵、缓行、偏航、减速、注意安全
- 距离：50/100/200/300/500/800 米、1 公里

播放时**前缀 + 动作**依次入队：`「三百米」+「前方左转」`。

体积 546 KB，分区占用 35%。

### 枚举索引的坑

`MOTO_VOICE_NONE = 0`，而数据表索引 0 是第一个真实片段。早期代码直接用枚举值索引：

```cpp
const int index = (int)phrase;   // 差一位，左转播出右转
```

已改为 `(int)phrase - 1`。

### 距离档位

向下取整，宁可说短：

| 实际距离 | 播报 |
| --- | --- |
| < 80 m | 不报距离 |
| 80–149 | 一百米 |
| 150–249 | 两百米 |
| 250–399 | 三百米 |
| 400–649 | 五百米 |
| 650–899 | 八百米 |
| ≥ 900 | 一公里 |

说 "五百米" 而实际 420 米，会让人提前期待转向；说 "三百米" 则留有小缓冲。

## 7. 时钟指针

### 长度固定 + 从文字背后穿过

早期尝试过"指针遇到文字自动缩短"，但会导致**分针比时针还短**，违反手表的直觉。

现在的做法：

- 三根指针长度固定（78 / 112 / 126 设计单位）
- 数字、日期、标题、副标题都有**不透明黑色底板**
- 指针经过时被底板遮住一截，视觉上从文字背后穿过

### 平滑扫动

秒针每秒走 6°，用 **420 ms smoothstep** 插值：

```cpp
double t = elapsed_ms / 420.0;
double eased = t * t * (3 - 2 * t);   // 起停平滑
return from + delta * eased;
```

**必须用时间驱动，不能用帧计数**：渲染频率不固定，帧计数缓动会让同一时刻产生不同角度，破坏渲染测试的确定性（这个坑实际踩过，测试直接失败）。

## 8. 页面切换

### 手势检测：不用 LVGL 的手势模块

LVGL 的 `LV_USE_GESTURE_RECOGNITION` 默认关闭，开启它**强制要求 `LV_USE_FLOAT`**，而后者会把 `lv_value_precise_t` 变成 float，导致地图几何代码大量 narrowing 错误。

所以改为自己检测**按下/释放的位置差**：

- 水平位移 > 屏宽 1/5（96 px）
- 且水平位移明显大于垂直位移（避免和列表滚动冲突）

### 页面锁定

导航数据每秒推送多次，每次都带"当前页 = 导航"。用户滑到其他页后，下一次推送就把页面顶回去，表现为**闪一下就退回**。

修复：手势翻页时设置 `user_selected_page`，之后忽略快照里的页码；滑回导航页才解除。

### 音乐播放导致的闪烁

`set_music_page_enabled()` 每次调用都会重排页面指示点，而音乐状态每秒推送多次。更糟的是音乐状态抖动时会把用户从音乐页踢走。

修复：加变化检测，值没变就直接返回。

## 9. 电量与信号

### 电量

来自 AXP2101：

- `0x34/0x35`：电压（14 bit，1 mV/LSB）
- `0xA4`：电量百分比
- `0x00` bit3：VBUS 在位

**充电判断的坑**：只看 `0x01` 的电流方向位会把"已充满"误判为未充电。实测插着 USB 且满电时 `0x01` 读数对应电流方向 0。现已改为 **VBUS 在位 OR 电流方向为充电**。

未接电池时显示 `--` 而非 0%。

### 信号

NimBLE 的 `ble_gap_conn_rssi()`，分四档：

| RSSI | 格数 |
| --- | --- |
| ≥ -60 dBm | 4 |
| ≥ -75 dBm | 3 |
| 更弱 | 2 |
| 断连 | 0 |

阈值故意做粗，避免手机在口袋里轻微移动时闪烁。

## 10. 音量按键

| 键 | 动作 |
| --- | --- |
| BOOT（GPIO0） | 音量 − |
| GPIO18 短按 | 音量 + |
| GPIO18 长按 3 秒 | 关机 |
| PWR | 仅电源（AXP2101 读中断状态） |

四档 `100 / 70 / 40 / 0`，存入 NVS。

### 提示音设计

- 加音量：**升调**（1200 → 1800 Hz）
- 减音量：**降调**（1800 → 1200 Hz）
- 到顶/到底：**低频闷响**（320 Hz），且**强制以 70% 音量播放**——静音时也要能听见"已经到底了"

早期两个方向用同一个提示音，且到极限时静音，导致用户以为按键失灵。

### 音量丢失的坑

编解码器空闲时会关闭（避免功放底噪），重新打开后**增益被重置**，而旧代码只在首次初始化时设置音量。所以第一次之后按音量键，声音大小都不变。

修复：每次重新打开 codec 时重新应用音量。

## 12. 内存与体积

| 项目 | 占用 |
| --- | --- |
| 固件 | 5.1 MB / 8 MB 分区（35% 剩余） |
| 语音片段 | 546 KB |
| 通知字体（16/20/28/34 px） | 约 14 MB 源文件，编译后约 2 MB |
| LVGL 中间层池 | 2 MB PSRAM |

### 字体体积的坑

通知卡片用 34 px 汉字字体，4bpp 下体积达 13 MB，编译后把只读段推入 PSRAM 过多，导致启动时 `ESP_ERR_NO_MEM`。

修复：28/34 px 降到 **2bpp**，体积砍半，画质无明显差异。

同时需要开启 `LV_FONT_FMT_TXT_LARGE`——大字体字形索引超过 16 bit。

## 14. 调试技巧

**判断固件版本**：不要看 `Compile time`——它只反映 `app_main.cpp` 的编译时刻。比对 `ELF file SHA256` 和本地 `moto_gps_esp32.elf` 的 sha256 才可靠。

**串口端口会变**：USB 重新枚举后 `usbmodem1101` 可能变成 `usbmodem3101`。用 `ls /dev/cu.usb*` 确认。

**深度睡眠**：PWR 长按 3 秒会调用 `esp_deep_sleep_start()`，此时串口无响应，按 GPIO18 唤醒。

**ANCS 排查顺序**：

1. 确认手机已锁屏
2. 确认"共享系统通知"已开
3. 看串口是否有 `notification event=`
4. 若完全没日志，考虑忽略设备后重新配对（ANCS 授权在首次配对时询问）
