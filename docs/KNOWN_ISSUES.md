# 已知问题与发布边界

本次公开的是 Waveshare 成品验证线的开发快照，不是验证通过的量产版本。

| 状态 | 问题 | 目前结论 |
| --- | --- | --- |
| 未关闭 | 离家后圆屏停留 `WAITING FOR PHONE` | BLE / iOS 后台状态恢复需继续定位；不是已经证明为手机没网。当前版本不保证锁屏长期保活 |
| 未关闭 | 临沂前往济南西站没有可选路线 | 需要复现并检查位置、网关请求/响应和上游服务状态；不能直接断言高德不支持跨城 |
| 待回归 | 真机路线与 App 预览不一致、出现绕路 | 路线选择传递已有逻辑与自动测试，但尚未完成对应跨城实车回归 |
| 待回归 | 快速转向时翻页/撕裂感 | 已有双缓冲、插值和 CO5300 TE 同步逻辑；实际流畅度、持续帧率与耗电仍需测量 |
| 固有边界 | 静止时绝对北向 | QMI8658 只有加速度计和陀螺仪，没有磁力计。手机在包里时不能把手机机身朝向当作车头方向 |
| 固有边界 | 济南之外背景路网 | 内置 OSM 数据只覆盖济南；其他城市没有同等离线灰路/建筑覆盖，不代表路线 API 不支持该城市 |
| 固有边界 | 限速、建筑缺失 | 依赖真实数据覆盖，不补画虚构内容；路线服务不总是给出可信法定限速 |
| 未验收 | 手机通知（ANCS）真实到达 | 订阅、属性读取与 ANCS 通道已在 2026-10-17 真机验证（ANCS ready、通知事件正常到达）；仍需确认通知卡片整屏显示与 BLE 不互相干扰的长时间表现。通知源是 iOS，网页没有对应数据源，无法替代 |
| 已修复 | 订阅瞬间的 ACL 拥塞 | iOS 在订阅建立后会重放整个通知中心的存量通知（均带 `PreExisting`），旧固件逐条回查正文，打满 ACL 缓冲（`ACL buf alloc failed` / `MBUF alloc stuck`）数秒。现已按 `PreExisting` 丢弃重放，实测失败计数归零 |
| 使用前提 | iOS 通知转发需要用户授权 | iOS 13 起由用户决定是否把通知转发给配件（设置 → 蓝牙 → 设备旁 ⓘ → 共享系统通知）。该开关关闭时，配对/加密/订阅全部正常但一条通知都收不到，容易被误判为固件缺陷 |
| 使用前提 | iOS 只在锁屏时转发 | 手机屏幕点亮且解锁时，iOS 把通知留在手机上；只有锁屏（或长时间无操作）时才会推给配件，因此现场验证必须先锁屏再触发 |
| 固有边界 | 通知文字的生僻字 | 通知标题/正文使用随固件的 GB2312 一级汉字字体，覆盖约 99.7% 日常中文；生僻字显示为占位方块 |
| 未验收 | 停车熄屏的省电收益 | 熄屏与停渲染的逻辑已有主机测试，但实际续航提升必须整车实测；不同供电组合（USB/电池）阈值可能不同 |
| 固有边界 | 电池续航、USB/电池组合关机、防水、抗振、骑行安全 | 成品开发板并非本项目认证的车规设备 |

本机演示用公共 POI 附近的真实 OSM 几何，可检查画面和动作关系，但不能验收实时路况、
真实定位精度、后台 BLE、手机蜂窝网络切换或真实导航正确性。

调试 BLE 时先停车：确认 App 前台是否恢复、iOS 蓝牙/定位权限、圆屏连接状态、
协议握手是否完成，再比对网关健康检查。不要用重启“偶尔成功”代替根因记录。
提交日志前删掉经纬度、设备 UUID、序列号、服务令牌等个人信息。
